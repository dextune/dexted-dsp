# 01. 산업용 GOAL, 고객, 지원 범위

## 1. 산업용이라는 말의 구체적 정의

본 프로젝트에서 산업용은 “긴 음원을 한 번 통과했다”는 뜻이 아닙니다. 계약된 입력 범위, 안정적인 API, 실제 고객의 계수로 검증한 근거, 제한된 실행 자원, 재현 가능한 배포 산출물, 결함 대응 책임이 함께 존재한다는 뜻입니다. 여기서의 산업용은 **비안전필수 영역의 오프라인 품질 검증 도구**입니다. 의료·자동차·항공·발전 설비의 기능 안전성 도구 자격은 별도 프로젝트이며 자동으로 따라오지 않습니다.

### 첫 고객과 도입 지점

| 우선순위 | 사용자와 현재 작업 | Dexted 도입 지점 | 구매·도입 가치 확인 방법 |
|---|---|---|---|
| P0 | 오디오 플러그인/EQ 개발자 | preset/export/build 시 최종 SOS를 인증 | 허용 이득 위반의 배포 차단, 수동 검토 시간 |
| P0 | 임베디드 오디오·계측 DSP 팀 | 펌웨어에 포함될 계수 blob의 승인 | 설계 계수와 실제 배포 비트의 일치, 추적 가능성 |
| P1 | 산업 센서·계측 필터 팀 | 보정·필터 설정 배포 전 검증 | 장기 신호 처리 문제와 이론적 규격을 분리 진단 |
| 범위 밖 | 범용 MIMO 폐루프 안전성·적응형 필터 | 첫 제품의 자동 승인 대상으로 삼지 않음 | 별도 모델과 검증 계약 없이는 지원 주장 금지 |

첫 도입의 합격은 고객 3개 프로젝트가 실제로 사용하고, 담당자가 인증 실패/UNKNOWN의 처리 방침을 이해하며, 배포 계수 해시를 다시 확인할 수 있는 상태입니다. 데모 저장소 3개를 자체 제작한 것은 독립 고객 3개가 아닙니다.

## 2. v1.0의 지원 계약

### MUST — 첫 산업용 릴리스에서 반드시 제공합니다

실수 계수, 정규화된 `a0=1`, 고정 계수 이산시간 SISO IIR의 전 대역 엄격 이득 한계 및 각 SOS 분모의 엄격 Schur 안정성을 검사합니다. 인증하는 것은 사용자가 제공한 최종 표현 계수입니다. 정규화·정밀도 변환·section 재배열은 인증 이전 단계에서 명시적으로 수행하고 결과를 다시 바인딩합니다.

산업용 성능 SLO를 우선 적용할 집합은 1~16 SOS입니다. 기존 17~32 SOS 지원을 제거하지 않되, 고차수·경계 사례는 별도 experimental/extended 계층으로 표시합니다. “API가 입력을 받는다”와 “성능·판정완결성까지 계약한다”를 혼동하지 않습니다. 정확성을 약화시키는 제한은 적용하지 않으며, 자원이 부족하면 UNKNOWN을 반환합니다.

Python의 인증 생성·검증·보고서 및 CLI가 첫 정식 제품의 기준 구현입니다. C++ f32 predicate는 별도 지원 표와 오류·메모리 경계 검토를 통과한 경우만 정식 지원합니다. C++ 인증서 생성까지 첫 릴리스에 무조건 넣지 않습니다. Python에서 검증한 배포 계수와 native 실행 계수의 바인딩은 필수입니다.

### SHOULD — 실제 도입을 위한 제품성

문서화된 배치 검사, 작업별 자원 제한, 취소·타임아웃, 실패 이유, 감사 로그, 재현 도구, 깨끗한 환경 설치, 장기 지원 정책, 버전별 인증서 호환성 표를 제공합니다. 실시간 audio callback 안에서 임의 정밀도 인증을 실행하지 않는 사용 구조를 예제로 보여줍니다.

### LATER — 별도 가설 검증을 거친 후에만 확장합니다

전체 SOS의 피크 주파수 위치 인증, 엄밀한 Hz 구간, runtime roundoff/state overflow 증명, fixed-point, 자동 보정, 적응형·시간가변 필터, MIMO, GPU, 새로운 OpenAI 수학 결과의 실행 통합입니다. 이것들을 모두 구현해야 현재의 오프라인 검증 제품이 출시 가능한 것은 아닙니다.

## 3. 정량 GOAL과 책임

**아래 값은 요구안이며 실측 성과가 아닙니다. G0에서 고객 요구와 기준 장비를 확정한 뒤 잠급니다.**

| ID | 목표 | 측정·합격 기준 | 실패 조치 / 책임 |
|---|---|---|---|
| IND-01 | 거짓 인증을 배포하지 않음 | 모든 평가에서 오라클 FAIL인데 CERTIFIED인 건수 0 | 단 1건도 출시 중단 / 수학 책임자 |
| IND-02 | 판정불능을 통과시키지 않음 | UNKNOWN·타임아웃·입력오류의 배포 통과 0 | 정책·통합 테스트 수정 / 코어·QA |
| IND-03 | 실제 자료 대표성 | 권한 확인된 제품 계수 3,000건, 독립 프로젝트 ≥3, 고정 holdout ≥1,000 | 실자료 게이트 미통과 / 데이터 책임자 |
| IND-04 | 일반 계수의 실용성 | ordinary 1~16 SOS의 사전 정의된 비경계 집합에서 UNKNOWN ≤0.1% | 예산·알고리즘 개선, 집합 사후 변경 금지 |
| IND-05 | 오프라인 지연 허용 | 1 biquad 인증+검증 p95 ≤5ms, 8 SOS p95 ≤250ms·p99 ≤1s | 기준 host에서 재측정; 성능 미달 공개 |
| IND-06 | 자원 상한 | 기본 core worker RSS 한도 256MiB, 작업 제한 5s, native 오류의 프로세스 탈출 0 | 무한 대기·OOM을 fail-closed 처리 |
| IND-07 | 장시간 자료 | 합성 24건·76 record-hours + 실자료 ≥20건 각 ≥30분 | 실제 길이·고유성·출처 미달은 제외가 아닌 미완료 |
| IND-08 | 운영 내구성 | 24h worker soak ×3, 승인 직전 72h soak ×1; 정당화되지 않은 지속 RSS 증가 없음 | 누수 조사, 재실행 / release·QA |
| IND-09 | 제3자 재현 | 서로 다른 장비군 ≥3, 외부 조직 ≥1의 정확성 재현 | 타이밍 일치가 아니라 판정·입력 일치로 평가 |
| IND-10 | 배포 공급망 | 버전·소스·wheel·native 빌드 추적, SBOM·출처 증거, clean install 전부 통과 | 배포 차단 / release |
| IND-11 | 도입 용이성 | 외부 개발자 10명 중 ≥9명이 15분 내 자기 계수 검사·실패 원인 확인 | 문서/진단/예제 수정 후 신규 사용자 재시험 |
| IND-12 | 운용 책임 | 소유자·보안 연락·결함 우선순위·rollback runbook·지원 범위 승인 | 정식 릴리스 명칭 사용 금지 |

IND-05~06은 대상 입력을 생략한 광고 수치로 사용하지 않습니다. 비경계 집합은 독립 오라클이 산출한 이득 여유 및 안정성 여유 기준으로 **실행 전에** 정의합니다. 숫자를 못 맞추면 기능 범위를 좁히거나 릴리스를 늦추되 정확성을 완화하지 않습니다.

## 4. 사용자의 최종 워크플로

`설계 → 배포 정밀도로 양자화 → 정확한 계수 추출 → 인증/독립 재검증 → 증거 저장 → 배포 직전 계수 해시 재검사 → 원래 DSP 엔진에 배포`를 기준으로 합니다.

성공 응답에는 대상 계수·이득 한계·샘플레이트 메타데이터·도구 버전·증명 범위가 명시됩니다. 실패 응답에는 gain 위반/불안정/입력 오류/판정불능을 구분합니다. FALSE PASS를 줄이는 이점과 지연·메모리·추가 유지비용을 함께 보여줍니다.

## 5. 비즈니스·엔지니어링 성과를 구별합니다

정확성: 오라클 대비 판정 혼동행렬과 인증서 재검증률입니다. 실용성: UNKNOWN 비율과 전체 작업 latency입니다. 도입 효과: 고객 배포 과정에서 검출한 결함, 추가된 검토 비용, 원인 조사 시간입니다. 사용자의 무조건적인 PASS 비율을 높이는 것은 목표가 아닙니다.

잘못된 필터를 고치거나 재설계하는 행위는 별도 기능입니다. 인증서가 거절되었다는 이유만으로 소리를 바꾸는 기능을 자동으로 수행하지 않습니다. “더 좋은 음질”, “기기 손상 방지”, “항상 더 빠름”은 본 시험 결과에서 도출하지 않습니다.

## 6. 출시 의사결정 원칙

필수 게이트의 결함을 다른 항목의 높은 점수로 상쇄하지 않습니다. 코드 작성자와 최종 정확성 승인자의 역할을 분리합니다. 외부 인력·고객 자료·배포 권한이 없으면 해당 항목은 BLOCKED입니다. AI 자체 리뷰는 사전 결함 발견에 사용하고 외부 검토 서명을 대체하지 않습니다.
